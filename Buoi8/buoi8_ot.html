1 Mô hình MVC là gì?

MVC (Model - View - Controller) là một kiến trúc phần mềm (design pattern) giúp tách biệt code thành 3 phần chính, làm cho ứng dụng dễ quản lý, bảo trì và mở rộng hơn.

Sơ đồ mô hình MVC

Mục tiêu của MVC:

  • Tách biệt trách nhiệm (Separation of Concerns)
  • Dễ bảo trì và mở rộng code
  • Hỗ trợ làm việc nhóm hiệu quả
  • Tái sử dụng code cao

2 Vai trò của từng thành phần

Model

Đại diện cho dữ liệu. Model tương tác với cơ sở dữ liệu, xử lý dữ liệu, kiểm tra tính hợp lệ dữ liệu.

  • • Lấy dữ liệu từ DB
  • • Thêm/Sửa/Xóa dữ liệu
  • • Xử lý quy tắc nghiệp vụ

View

Phần giao diện người dùng. Chỉ chứa HTML, CSS, JavaScript và một chút logic PHP để hiển thị dữ liệu (không chứa logic phức tạp).

  • • Hiển thị form
  • • Hiển thị dữ liệu từ Controller
  • • Gửi request đến Controller

Controller

Bộ não của ứng dụng. Nhận request từ người dùng, xử lý logic, gọi Model lấy dữ liệu và trả về View.

  • • Xử lý form submission
  • • Gọi Model
  • • Trả dữ liệu về View

3 Ví dụ: Xử lý form đăng nhập trong 1 file

login.php (cách truyền thống) 

<?php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $username = $_POST['username'] ?? '';
    $password = $_POST['password'] ?? '';
    
    // Logic xử lý
    if ($username === 'admin' && $password === '123') {
        echo "<div class='success'>Đăng nhập thành công!</div>";
    } else {
        echo "<div class='error'>Sai thông tin đăng nhập!</div>";
    }
}
?>

<form method="POST">
    <input type="text" name="username" placeholder="Tên đăng nhập" required><br>
    <input type="password" name="password" placeholder="Mật khẩu" required><br>
    <button type="submit">Đăng nhập</button>
</form>

Nhược điểm của cách làm này:

  • Code HTML và PHP logic lẫn lộn → khó đọc, khó bảo trì
  • Khó tái sử dụng code ~ nếu muốn có logic tương tự gần như phải viết lại
  • Không tách biệt được logic business với giao diện
  • Dễ bị tấn công (SQL Injection, XSS) nếu không xử lý cẩn thận
  • Không phù hợp với dự án lớn

4 Triển khai lại bằng mô hình MVC

Cấu trúc thư mục cơ bản:

project/
├── app/
│   ├── Controllers/
│   │   └── AuthController.php
│   ├── Models/
│   │   └── User.php
│   └── Views/
│       └── auth/
│           └── login.php
├── public/
│   └── index.php
├── routes/
│   └── router.php
└── config/
    └── database.php

Mô tả các file chính:

  • public/index.php: Entry point, khởi tạo session và load tất cả file. Mội request của người dùng sẽ phải đi qua file này
  • routes/router.php: Xử lý routing. Định tuyến request người dùng và gọi controller tương ứng
  • AuthController.php: Xử lý logic đăng nhập theo chuẩn .
  • User.php: Model xử lý business logic và thao tác với cơ sở dữ liệu.

1. Model - app/Models/User.php 

<?php
// app/Models/User.php
class User {
    public function login($username, $password) {
        if ($username === 'admin' && $password === '123') {
            return [
                'success' => true,
                'user' => ['id' => 1, 'name' => 'Admin']
            ];
        }
        return [
            'success' => false,
            'message' => 'Tên đăng nhập hoặc mật khẩu không đúng!'
        ];
    }
}

2. Controller - app/Controllers/AuthController.php 

<?php
// app/Controllers/AuthController.php

class AuthController {
    
    private $userModel;

    public function __construct() {
        $this->userModel = new User();
    }

    public function login() {
        $error = '';

        // Xử lý POST (submit form)
        if ($_SERVER['REQUEST_METHOD'] === 'POST') {
            $username = trim($_POST['username'] ?? '');
            $password = trim($_POST['password'] ?? '');

            $result = $this->userModel->login($username, $password);

            if ($result['success']) {
                $_SESSION['user'] = $result['user'];
                header('Location: /dashboard');
                exit;
            } else {
                // Lưu lỗi vào session và redirect về GET
                $_SESSION['login_error'] = $result['message'];
                header('Location: /login');
                exit;
            }
        }

        // Xử lý GET - Hiển thị form
        if (isset($_SESSION['login_error'])) {
            $error = $_SESSION['login_error'];
            unset($_SESSION['login_error']); // Xóa sau khi hiển thị
        }

        // Hiển thị View
        require_once __DIR__ . '/../../Views/auth/login.php';
    }
}

3. Router - routes/router.php 

<?php
// routes/router.php

$uri = $_SERVER['REQUEST_URI'];
$parsed = parse_url($uri);

$path = $parsed['path'] ?? '/';
$queryString = $parsed['query'] ?? '';
$queryParams = [];
if ($queryString) {
    parse_str($queryString, $queryParams);
}


switch ($path) {
    case '/':
    case '/login':
        $controller = new AuthController();
        $controller->login();
        break;

    case '/dashboard':
        echo "Chào mừng đến Dashboard!";
        break;

    default:
        http_response_code(404);
        echo "404 - Trang không tồn tại";
        break;
}

4. Entry Point - public/index.php 

<?php
// public/index.php

// Khởi tạo session một lần duy nhất ở Entry Point
session_start();

// Load các file cần thiết
require_once __DIR__ . '/../app/Models/User.php';
require_once __DIR__ . '/../app/Controllers/AuthController.php';

// Gọi Router
require_once __DIR__ . '/../routes/router.php';

Ưu và Nhược điểm của mô hình MVC

Ưu điểm

  • Tách biệt rõ ràng giữa logic, dữ liệu và giao diện (Separation of Concerns)
  • Dễ bảo trì và mở rộng khi dự án lớn
  • Hỗ trợ làm việc nhóm hiệu quả (mỗi người có thể làm một phần riêng)
  • Dễ viết Unit Test cho Controller và Model
  • Tái sử dụng code cao
  • Code rõ ràng, dễ đọc và chuyên nghiệp

Nhược điểm

  • Phức tạp hơn so với cách viết PHP truyền thống (nhiều file, nhiều lớp)
  • Khúc xạ học ban đầu khá cao với người mới
  • Dễ over-engineering (làm quá phức tạp) với các dự án nhỏ
  • Số lượng file tăng nhiều, cấu trúc thư mục phức tạp hơn
  • Hiệu suất hơi giảm so với cách viết một file (do phải load nhiều file)
Kết luận: MVC rất phù hợp với dự án trung bình và lớn. Với dự án nhỏ, có thể dùng cách đơn giản hơn trước khi chuyển sang MVC.
