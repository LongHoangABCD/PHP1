1 Tính Đóng Gói (Encapsulation) là gì?

Tính đóng gói là một trong 4 tính chất cốt lõi của OOP. Nó cho phép chúng ta che giấu dữ liệu (thuộc tính) và hành vi (phương thức) của một lớp (class) khỏi các truy cập trực tiếp từ bên ngoài.
Đồng thời cung cấp các phương thức công khai để bên ngoài có thể truy cập được

Mục tiêu chính:

  • Bảo vệ dữ liệu khỏi truy cập trực tiếp không an toàn
  • Kiểm soát cách dữ liệu được đọc và thay đổi
  • Dễ dàng bảo trì và mở rộng code

2 Phạm vi truy cập (Access Modifiers)

Phạm vi Từ khóa Tác dụng Ứng dụng
Công khai public Là phạm vi rộng nhất.
Có thể truy cập ở bất kỳ đâu cả bên trong và bên ngoài class 		Dùng cho Getter & Setter hoặc các phương thức công khai cần gọi từ bên ngoài class
Riêng tư private Che giấu hoàn toàn thuộc tính hoặc phương thức, không cho phép truy cập trực tiếp từ bên ngoài class. Phạm vi được dùng nhiều nhất cho thuộc tính
Bảo vệ protected Có thể truy cập bên trong class đó và trong các class con kế thừa Dùng cho thuộc tính/phương thức khi muốn cho class con kế thừa sử dụng

Để thực hiện tính đóng gói, chúng ta cần sử dụng các phạm vi truy cập một cách có chủ đích.

Quy tắc thực tế khi áp dụng Tính Đóng Gói:

  • Bước 1: Khai báo thuộc tính Nên khai báo thuộc tính với phạm vi private (che giấu hoàn toàn) hoặc protected.
  • Bước 2: Cung cấp phương thức công khai
    • Getter & Setter: Khai báo public để cho phép bên ngoài truy cập và thay đổi dữ liệu có kiểm soát.
    • Các phương thức công khai khác: Khai báo public nếu cần gọi từ bên ngoài class.
  • Lưu ý quan trọng: Tránh khai báo thuộc tính public (trừ một số trường hợp đặc biệt).

3 Getter & Setter

Khi thuộc tính được khai báo private hoặc protected, ta không thể truy cập trực tiếp từ bên ngoài. Lúc này, Getter và Setter đóng vai trò là "cửa ngõ" an toàn để đọc và ghi dữ liệu.

Ví dụ cơ bản:

<?php
class Person {
    private $name;
    private $age;

    // Getter
    public function getName() {
        return $this->name;
    }

    public function getAge() {
        return $this->age;
    }

    // Setter
    public function setName($name) {
        if (empty($name)) {
            echo "Tên không được để trống!";
            return;
        }
        $this->name = $name;
    }

    public function setAge($age) {
        if ($age < 0 || $age > 150) {
            echo "Tuổi không hợp lệ!";
            return;
        }
        $this->age = $age;
    }
}
?>
Tại sao phải dùng Getter & Setter thay vì truy cập trực tiếp?

Giả sử thuộc tính $name và $age được khai báo public, chúng ta có thể viết: 

$person->name = "";     // Không kiểm soát được
$person->age  = -50;     // Dữ liệu không hợp lệ

Vấn đề khi truy cập trực tiếp:

  • Dễ gán dữ liệu sai (tên rỗng, tuổi âm, tuổi quá lớn...).
  • Khó kiểm soát logic, dữ liệu có thể bị lấy, sửa một cách tuỳ tiện.
  • Vi phạm nguyên tắc Tính Đóng Gói (che dấu dữ liệu bên trong class).
  • Khó bảo trì sau này khi cần thay đổi quy tắc.

Lợi ích khi dùng Getter & Setter:

  • Kiểm soát dữ liệu (Validation): Do nó là một hàm, ta hoàn toàn có thể viết các logic if..else, kiểm tra dữ liệu trước khi gán (như ví dụ trên).
  • Bảo vệ dữ liệu: Thuộc tính private không thể bị thay đổi trực tiếp từ bên ngoài.
  • Dễ mở rộng: Sau này có thể thêm logic (ví dụ: ghi log, cập nhật timestamp, kiểm tra quyền...).
  • Code rõ ràng và an toàn hơn.

Kết luận: Getter & Setter chính là cách thực hiện tính đóng gói một cách hiệu quả nhất. Chúng cho phép bên ngoài truy cập dữ liệu có kiểm soát thay vì truy cập trực tiếp và không an toàn.

4 Ví dụ thực tế: Quản lý tài khoản ngân hàng

Dưới đây là một ví dụ thực tế minh họa rõ nhất lợi ích của Tính Đóng Gói trong lập trình.

Code ví dụ:

<?php
class BankAccount {
    private $accountNumber;
    private $balance = 0;

    public function __construct($accountNumber) {
        $this->accountNumber = $accountNumber;
    }

    public function getBalance() {
        return $this->balance;
    }

    public function deposit($amount) {
        if ($amount > 0) {
            $this->balance += $amount;
            echo "Nạp tiền thành công: " . number_format($amount) . " VNĐ\n";
        }
    }

    public function withdraw($amount) {
        if ($amount > 0 && $amount <= $this->balance) {
            $this->balance -= $amount;
            echo "Rút tiền thành công: " . number_format($amount) . " VNĐ\n";
        } else {
            echo "Số dư không đủ hoặc số tiền không hợp lệ!\n";
        }
    }
}

// Sử dụng
$account = new BankAccount("123456789");
$account->deposit(5000000);
$account->withdraw(2000000);
echo "Số dư hiện tại: " . number_format($account->getBalance()) . " VNĐ";
?>
Phân tích chi tiết ví dụ này:

1. Tính Đóng Gói được thể hiện qua:

  • private $accountNumber và private $balance: Hai thuộc tính này được che giấu hoàn toàn. Bên ngoài không thể truy cập trực tiếp (không thể viết $account->balance = 1000000000;).
  • Chỉ có thể tương tác với tài khoản thông qua các phương thức công khai (public): deposit(), withdraw(), getBalance().

2. Tại sao không cho phép truy cập trực tiếp? 

// Cách nguy hiểm (nếu balance là public)
$account->balance = -5000000;        // Số dư âm không hợp lệ
$account->balance = "một triệu";     // Sai kiểu dữ liệu

3. Lợi ích khi dùng Tính Đóng Gói trong ví dụ này:

  • Kiểm soát logic kinh doanh: Phương thức withdraw() kiểm tra số dư trước khi cho rút tiền.
  • Bảo vệ dữ liệu quan trọng: Không ai có thể tự ý thay đổi số dư mà không qua quy trình.
  • Dễ bảo trì: Nếu sau này ngân hàng thay đổi quy tắc (ví dụ: phí rút tiền, giới hạn rút tối đa một ngày), chỉ cần sửa trong class, không ảnh hưởng đến code bên ngoài.
  • Tăng tính an toàn: Tránh các lỗi vô ý hoặc cố ý làm hỏng dữ liệu.

Kết luận: Đây chính là tinh thần cốt lõi của Tính Đóng Gói — “Ẩn đi chi tiết bên trong, chỉ cung cấp giao diện an toàn và có kiểm soát cho bên ngoài sử dụng.”
